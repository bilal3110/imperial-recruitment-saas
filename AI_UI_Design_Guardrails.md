# AI UI Design Direction & Anti-Generic Design Rules

## Purpose

Use this document as a **design guardrail** before generating any UI, landing page, dashboard, SaaS interface, web app, or component.

The goal is NOT to make every design weird or experimental.

The goal is to prevent the AI from automatically falling back to the same generic "AI-generated SaaS" aesthetic and instead produce interfaces with a distinct visual identity, strong hierarchy, intentional composition, and product-specific character.

---

# 1. Core Principle

Do not design from the phrase:

> "modern SaaS UI"

Design from:

> **Product purpose + target audience + visual direction + information hierarchy + constraints**

Every design decision should have a reason.

Do not add visual elements simply because they are common in modern web design.

**Avoid the statistical average of the internet.**

---

# 2. NEVER Automatically Use These Patterns

Unless explicitly requested, DO NOT default to:

- Purple/blue AI gradients
- Blue-purple gradient backgrounds
- Glowing gradient blobs
- Glassmorphism
- Frosted glass cards
- Excessive blur
- Floating 3D objects
- Generic AI sparkles
- Gradient text
- Huge centered hero headings
- Giant dashboard screenshots inside browser mockups
- Excessive rounded cards
- Every section inside a card
- Excessive pill-shaped UI
- Floating cards with random shadows
- Excessive drop shadows
- Generic SaaS illustrations
- Generic abstract blobs
- Random decorative circles
- Excessive animated elements
- "AI" visual clichés
- Stock-looking human illustrations
- Fake charts used only for decoration
- Repeated card grids everywhere
- Generic metric cards for every piece of information
- "Trusted by 10,000+ companies" sections unless the product actually has this
- Fake testimonials
- Fake logos
- Fake statistics
- Fake customer data
- Copy that sounds like every startup website
- Excessive whitespace with very little useful information
- Overly dense interfaces with no hierarchy
- Making every component visually prominent
- Making every corner rounded
- Using the same border radius everywhere
- Using the same card component repeatedly without contextual reason

Do not assume that "modern" means:

> rounded + gradient + glass + shadow + huge typography.

---

# 3. Avoid the "AI Website" Look

The final result should NOT immediately look like it was generated by an AI UI generator.

A viewer should be able to imagine that a real design team created it for a specific product.

Ask:

- What makes this interface recognizable?
- What visual language belongs specifically to this product?
- What would make this design different from 100 other SaaS products?
- Does the layout communicate the product's actual purpose?
- Are visual elements helping usability or merely decorating the page?

If removing the gradients and shadows makes the design indistinguishable from another SaaS website, the design is probably too generic.

---

# 4. Establish a Visual Direction BEFORE Designing

Before generating the interface, define:

### Product Character

Choose 3–5 meaningful adjectives.

Examples:

- Technical
- Editorial
- Precise
- Experimental
- Calm
- Premium
- Industrial
- Playful
- Serious
- Scientific
- Operational
- Trustworthy
- Minimal
- Bold
- Human

Do NOT automatically use:

- Modern
- Sleek
- Futuristic
- Innovative
- Cutting-edge

These words are too vague and usually produce generic results.

---

# 5. Use Cross-Industry References

Do not limit visual inspiration to other SaaS products.

Consider borrowing visual principles from:

- Editorial magazines
- Newspapers
- Scientific journals
- Cybersecurity software
- Developer tools
- IDEs
- Financial terminals
- Aviation interfaces
- Industrial control systems
- Medical software
- Architecture
- Swiss graphic design
- Japanese industrial design
- Railway signage
- Maps
- Technical manuals
- Luxury fashion
- Film title sequences
- Data visualization
- Government systems
- Gaming interfaces
- Physical products
- Packaging design

The reference should influence the **design language**, not be copied literally.

Example:

Instead of:

> "Make a cybersecurity SaaS dashboard."

Try:

> "Use the visual discipline of a professional security operations console: dense information hierarchy, restrained color usage, clear severity levels, evidence-oriented layouts, and technical typography."

---

# 6. Typography Rules

Typography should establish hierarchy, not decoration.

Prefer:

- Strong typographic hierarchy
- Clear heading/body contrast
- Intentional font pairing
- Appropriate line lengths
- Comfortable reading rhythm
- Distinct treatment for technical information
- Monospace fonts where they genuinely communicate technical data

Avoid:

- Using giant typography everywhere
- Making every heading oversized
- Using multiple decorative fonts
- Using monospace text just because the product is "AI"
- Excessive letter spacing
- Gradient text
- Typography that sacrifices readability for aesthetics

Typography should feel intentional and product-specific.

---

# 7. Color Rules

Use color with purpose.

Start with:

- A strong neutral foundation
- One primary accent
- Optional secondary semantic colors

Color should communicate:

- Hierarchy
- Status
- Severity
- Interaction
- Brand identity
- Important information

Avoid:

- Rainbow interfaces
- Multiple competing accent colors
- Purple/blue gradients by default
- Neon colors without product justification
- Making every element colorful
- Using color where typography or spacing would communicate better

A restrained palette is often more distinctive than a visually noisy one.

---

# 8. Layout Rules

Do not automatically use:

> Navbar → centered hero → three cards → feature grid → testimonials → CTA → footer

That structure is acceptable only when it actually fits the product.

Explore:

- Asymmetrical layouts
- Editorial layouts
- Split compositions
- Dense information layouts
- Horizontal storytelling
- Vertical timelines
- Full-width sections
- Edge-to-edge content
- Strong visual anchors
- Overlapping elements when useful
- Unusual but usable navigation
- Content-first layouts
- Data-first layouts

Break symmetry when it improves hierarchy.

Do not create asymmetry just to appear "creative."

---

# 9. Cards Are Not the Default Answer

Cards are useful, but AI tends to turn everything into cards.

Before creating a card, ask:

> Does this information actually need to be visually separated?

Alternatives include:

- Tables
- Lists
- Dividers
- Inline sections
- Side panels
- Tabs
- Timelines
- Expandable rows
- Editorial blocks
- Full-width sections
- Dense data layouts
- Split views

If the entire page consists of rounded rectangles, rethink the composition.

---

# 10. Spacing Rules

Whitespace should communicate hierarchy.

Do not add large empty spaces simply because:

> "Minimal design = lots of whitespace."

Instead:

- Group related information
- Separate unrelated information
- Establish rhythm
- Create visual priority
- Control scanning behavior

Dense interfaces can be beautiful when information is structured correctly.

Minimalism is not the same thing as emptiness.

---

# 11. Component Variety

Components should respond to their content.

Do not use:

> Card + icon + heading + paragraph

for every feature.

Instead consider:

- Tables
- Timeline
- Progress indicators
- Charts
- Lists
- Feature comparisons
- Large statistics
- Evidence panels
- Side-by-side comparisons
- Expandable sections
- Activity feeds
- Command interfaces
- Filters
- Search
- Status indicators
- Contextual actions
- Inline editing
- Empty states
- Detail views

Component choice should follow **information type**.

---

# 12. Information Hierarchy Comes First

Every screen should have a clear answer to:

1. What is the most important thing?
2. What should the user notice second?
3. What action should the user take?
4. What information can be secondary?
5. What information can be hidden until needed?

Do not make everything equally important.

Visual hierarchy should come from a combination of:

- Size
- Position
- Spacing
- Typography
- Contrast
- Density
- Color
- Grouping

Not just shadows and gradients.

---

# 13. Design For The Product, Not The Trend

The interface should reflect what the product actually does.

Examples:

### Developer Tool

Favor:

- Technical typography
- Logs
- Tables
- Command-style interactions
- Structured data
- Dense layouts

### Financial Product

Favor:

- Precision
- Data hierarchy
- Numerical readability
- Tables
- Clear status
- Strong comparison patterns

### Creative Product

Favor:

- Visual previews
- Canvas-oriented layouts
- Flexible composition
- Larger visual elements

### Enterprise Software

Favor:

- Efficiency
- Search
- Filtering
- Tables
- Bulk actions
- Clear permissions/status

### Consumer Product

Favor:

- Simplicity
- Strong onboarding
- Clear actions
- Friendly visual hierarchy

Do not force one universal design language onto every product.

---

# 14. Use Motion Carefully

Animation should communicate:

- State changes
- Relationships
- Navigation
- Progress
- Feedback
- Spatial transitions

Avoid animation whose only purpose is:

> "Make it look cool."

Do not automatically add:

- Parallax everywhere
- Floating animations
- Constant movement
- Scroll-triggered effects to every section
- Glowing elements
- Excessive hover animations

Motion should improve understanding, not compete with the content.

---

# 15. Content Must Feel Real

Do not use generic filler such as:

> "Transform your workflow with next-generation AI."

Prefer product-specific language.

UI content should represent realistic:

- Labels
- Data
- Statuses
- Errors
- Empty states
- User actions
- Settings
- Results
- Notifications

If real data is unavailable, create believable placeholder data that matches the product.

Do not fabricate social proof, companies, statistics, testimonials, or claims.

---

# 16. Design For States, Not Just Screenshots

Every important interface should consider:

- Loading
- Empty
- Success
- Error
- Warning
- Disabled
- Partial data
- Long content
- No results
- Permission restrictions
- First-time user
- Returning user

A beautiful screenshot is not a product.

The UI needs to survive actual usage.

---

# 17. Accessibility Is Part of Design

Prioritize:

- Readable contrast
- Keyboard navigation
- Clear focus states
- Understandable labels
- Appropriate text sizes
- Non-color-only status communication
- Sufficient touch targets
- Logical hierarchy

Do not sacrifice usability for visual novelty.

---

# 18. Avoid Design Homogenization

Do not copy the visual language of:

- Linear
- Notion
- Stripe
- Vercel
- Apple
- OpenAI
- Framer
- Raycast
- Arc
- Generic Tailwind templates

These can be references, but do not reproduce their recognizable patterns unless explicitly requested.

The goal is not:

> "Make it look like Linear."

The goal is:

> "Understand why a design works, then create an original visual system appropriate for this product."

---

# 19. Before Generating, Produce Multiple Directions

When the design brief is ambiguous, generate **3 genuinely different visual directions**.

Example:

### Direction A: Editorial

- Strong typography
- Asymmetric grid
- Minimal decoration
- Magazine-inspired hierarchy

### Direction B: Technical

- Dense information
- Monospace accents
- Tables
- Precise borders
- Developer-tool aesthetic

### Direction C: Industrial

- Strong blocks
- Operational dashboard patterns
- Clear status indicators
- Functional visual language

These should differ in:

- Layout
- Typography
- Color strategy
- Density
- Components
- Visual references

Do not generate three versions that are essentially the same layout with different colors.

---

# 20. Design Review Checklist

Before finalizing a design, evaluate it against these questions:

### Originality

- [ ] Does this look different from a typical AI-generated SaaS design?
- [ ] Could I identify the product without seeing the logo?
- [ ] Does it have a recognizable visual language?
- [ ] Did we avoid default AI aesthetics?

### Product Fit

- [ ] Does the UI reflect the actual product?
- [ ] Are components appropriate for the information?
- [ ] Is the hierarchy logical?
- [ ] Does the design prioritize user tasks?

### Visual Quality

- [ ] Is typography intentional?
- [ ] Is spacing consistent?
- [ ] Is color purposeful?
- [ ] Are cards being used appropriately?
- [ ] Is there unnecessary decoration?

### Usability

- [ ] Is important information easy to find?
- [ ] Are actions obvious?
- [ ] Are states handled?
- [ ] Is the interface accessible?
- [ ] Does it still work without animations?

---

# 21. Anti-Generic Final Test

Before delivering the design, ask:

> **If I remove the logo, brand name, and colors, would this still look like it could belong to 50 other SaaS products?**

If the answer is yes:

**Redesign it.**

Then ask:

> **What specific visual decisions make this product different?**

There should be a clear answer.

---

# 22. Default Design Philosophy

Unless the user explicitly requests otherwise:

**Prefer:**

- Intentional over trendy
- Product-specific over generic
- Clear over decorative
- Distinctive over fashionable
- Functional over ornamental
- Restrained over noisy
- Structured over random
- Human-designed feeling over AI-generated feeling

**Remember:**

> Modern does not mean generic.

> Minimal does not mean empty.

> Premium does not mean glassmorphism.

> AI does not mean purple gradients.

> Creative does not mean random.

> Beautiful does not mean unusable.

The objective is to create a **distinct visual system**, not merely a polished screenshot.
